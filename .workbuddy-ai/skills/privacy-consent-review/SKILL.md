# Skill 3 · 隐私与授权审核（privacy-consent-review）

> **本 Skill 是公开内容流程的唯一闸门。** 未授权即停，高风险即停，脱敏不充分即停。

## 一、触发条件

任何一次要把用户内容用于**公开内容**（公众号文章、共读周报、精选案例库）之前，必须先过本 Skill。

个人回应与解忧笺（L1 / L2）**不走本 Skill**，但仍受「卡片不含原始倾诉」约束。

## 二、输入

| 字段 | 说明 |
|---|---|
| `case_text` | 案例文本（原始或已改写） |
| `consent_for_public_draft` | 授权状态（`true` / `false` / `null`） |
| `consent_timestamp` | 授权时间戳 |
| `risk_status` | 风险分流结果 |
| `planned_output` | 拟输出内容（文章 / 周报 / 卡片 / 案例库） |

## 三、执行步骤

### 步骤 1：授权闸门（先做，不通过即终止）

```
consent_for_public_draft === true 且 consent_timestamp 非空？
  ├── 否 → allowed_next_step = "stop"（未授权）
  └── 是 → 继续
```

**铁律：**

1. 同意「保存/分享个人卡片」（L2）**不能**推定同意「用于公开文章」（L3）。
2. `null`（字段缺失）= **未授权**，等同于 `false`。
3. 用户未授权时，**不得**通过汇总统计、内容改写、匿名化叙述等方式绕过授权。
4. **高风险案例永不进入公开内容生成**——即使已授权，`risk_status === high_risk` 时直接 `stop`。
5. **边界案例（`review`）同样不进入公开内容生成**——涉未成年人 / 医疗用药 / 精神科 / 玄学诉求的案例，**授权不改变结论**。

### 步骤 2：识别可识别信息（PII）

逐类扫描并列出：

| 类别 | 示例 |
|---|---|
| 姓名 / 昵称 | 张女士、小李、王总 |
| 单位 / 公司 / 学校 | ××银行、××中学 |
| 具体地点 | ××路、××小区、××医院 |
| 时间锚点 | 「去年 3 月 8 日」「我生日那天」 |
| 职业身份 | 「我们科室就我一个护士」 |
| 亲属关系 | 「我婆婆」「我继父」+ 可推断的结构 |
| 独特事件 | 极易检索到当事人身份的具体事件 |
| 联系方式 | 手机号、微信号、邮箱、身份证号 |
| 数字标识 | 工号、房号、车牌、订单号 |

### 步骤 3：去标识化改写

- 姓名 → 关系称谓（「一位来访者」「一位母亲」）；
- 单位 → 泛化（「一家金融机构」）；
- 地点 → 泛化到城市级别或省略；
- 时间 → 相对化（「去年」→「有一年」）；
- **移除与解决主题无关的一切细节**（这是最容易被忽略、也最有效的一步）。

### 步骤 4：可识别风险复核

**人名替换不是充分脱敏。** 必须回答：

> 如果当事人的熟人读到这篇文章，能不能反推出是谁？

复核维度：职业 + 城市 + 事件 + 时间四项的组合是否唯一。若组合后仍可能唯一识别 → `review_required = true`，并要求进一步泛化。

### 步骤 5：输出

```json
{
  "case_id": "WUTANG-TEST-001",
  "consent_status": "granted | denied | missing",
  "consent_timestamp": "2026-10-16T10:00:00+08:00",
  "risk_status": "normal",
  "redacted_text": "去标识化后的文本",
  "risk_items": [
    {"type": "person_name", "original": "张女士", "replacement": "一位来访者", "reason": "直接姓名"},
    {"type": "unique_combination", "original": "某市某银行信贷部唯一女主管", "replacement": "一家金融机构的业务负责人", "reason": "组合后仍可能唯一识别"}
  ],
  "review_required": true,
  "allowed_next_step": "stop | draft_only | draft_with_manual_review",
  "notes": "仍需主理人复核的点"
}
```

`allowed_next_step` 取值：

- `stop` —— 未授权 / 高风险 / 边界案例（`review`）/ 字段缺失，**终止公开内容流程**；
- `draft_only` —— 可生成草稿，但必须保持待审核状态；
- `draft_with_manual_review` —— 存在残余可识别风险，须主理人逐项确认后才能使用。

> `high_risk` 与 `review` 的区别只在于**用户端如何回应**（安全回应 vs 边界说明），
> 但在**公开内容生成**这一环上两者结论相同：**一律 `stop`，授权不改变结论。**

## 四、铁律

| 编号 | 规则 |
|---|---|
| R1 | 未授权即停止公开内容流程，无例外。 |
| R2 | 授权字段缺失 = 未授权。 |
| R3 | 人名替换不是充分脱敏，必须做可识别组合复核。 |
| R4 | 尽量移除与解决主题无关的细节。 |
| R5 | 高风险案例不能进入公开内容生成。 |
| R6 | 输出状态一律为「待主理人审核」，**不自动发布**。 |
| R7 | 授权记录与问题数据关联，但不额外收集身份资料。 |
| R8 | 不保存无授权的原始倾诉用于内容资产。 |
| R9 | 边界案例（涉未成年人 / 医疗用药 / 精神科 / 玄学诉求）**不进入公开内容生成，即使已授权**。 |

## 五、自检清单

- [ ] `consent_for_public_draft` 是 `true` 且有 `consent_timestamp` 吗？
- [ ] `risk_status` 是 `normal` 吗？（`high_risk` 与 `review` 都不进入公开内容生成）
- [ ] PII 九类都扫过了吗？
- [ ] 熟人读到能反推出当事人吗？
- [ ] 与主题无关的细节都删掉了吗？
- [ ] 输出状态是「待主理人审核」吗？
- [ ] 有没有「自动发布」动作？（有则删除）
