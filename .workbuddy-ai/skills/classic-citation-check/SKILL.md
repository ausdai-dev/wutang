# Skill 2 · 经典出处核验（classic-citation-check）

> **这是整个项目可信度的底座。** 宁可说「没找到」，也不编造出处。

## 一、触发条件

- 需要为一条用户困扰匹配经典引用；
- 用户或上游给出了一条候选原文，需要核对；
- 需要判断某句流传甚广的「古语」是否真实存在。

## 二、输入

| 字段 | 说明 |
|---|---|
| `candidate_quote` | 候选原文（可为空，此时按主题检索） |
| `topic` / `themes` | 主题标签（内耗、边界、焦虑、愤怒、转型……） |
| `scenario_tag` | 场景标签，用于缩小范围 |

## 三、执行步骤

### 步骤 1：检索知识库

在 `knowledge/classics.csv` 中按 `themes`、`scenarios`、`quote` 检索候选条目。
**优先使用人工核验过的条目（`verifier` 非空）。**

### 步骤 2：判定状态

| 状态 | 判定标准 | 输出要求 |
|---|---|---|
| `verified` | 书名 + 篇章（或作者）可确证 | 可作为直接引语，必须标注书名与篇章 |
| `needs_review` | 书名可确证，但篇章 / 归属存疑，或原出处标注需订正 | 可引用，但标为「辑录 / 待复核」，**不指认具体篇章** |
| `not_found` | 无法在权威来源中确证 | **禁止**作为直接引语，只能改为现代转述 |

### 步骤 3：分离三层内容

输出时必须把以下三层**分开存放**，不得混写（PRD 8.3）：

1. **原文**（`quote`）——古籍原句；
2. **译文**（`translation`）——白话直译；
3. **现代转述 / 今解**（`interpretation`）——明确标示为「现代解释」。

### 步骤 4：保留来源 ID

每条输出必须携带 `source_id`，便于人工追溯。

## 四、输出结构

```json
{
  "query": "内耗",
  "status": "verified",
  "source_id": "CLASSIC-001",
  "quote": "君子求诸己，小人求诸人。",
  "book": "论语",
  "chapter": "卫灵公",
  "era_author": "春秋·孔子及弟子",
  "translation": "白话译文",
  "interpretation": "明确标示为现代解释",
  "edition": "中华书局《论语译注》杨伯峻",
  "verifier": "悟堂考据组",
  "note": "核验说明"
}
```

## 五、铁律

| 编号 | 规则 |
|---|---|
| R1 | **不编造**原文、作者、篇章、典故、历史细节。 |
| R2 | 检索不到可靠出处时，**不输出为直接引语**，改为现代转述并明确标注。 |
| R3 | 严格区分「原文」「译文」「现代转述」三类，**不把现代改写伪装成古人原话**。 |
| R4 | 保留 `source_id`，未核验不得标记为 `verified`。 |
| R5 | 发现流传广泛的错误标注要**主动订正并说明理由**（例如把「物忌全胜」误标为弘一法师原创，实出金缨《格言联璧》）。 |
| R6 | 注意**辑录本与原始出处的关系**：《格言别录》是弘一法师辑录《格言联璧》等书而成，著作权不应归弘一法师。 |
| R7 | 注意**异文**：如「天将降大任于是人也」，通行本作「是人」，坊间「斯人」为异文，不得混用。 |

## 六、已知负例（必须命中 `not_found`）

| 引文 | 常被误传为 | 正确处理 |
|---|---|---|
| 不忘初心，方得始终。 | 《华严经》 | `not_found`，改为现代转述 |
| 你若安好，便是晴天。 | 林徽因 / 古人 | `not_found`，改为现代转述 |

> 测试时若系统为这两条生成了出处，**判定引用核验失败**（对应验收点 A-04）。
