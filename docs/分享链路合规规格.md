## 0. 分层定义（先划范围，再定规则）

| 层 | 行为 | 是否过本规格 | 授权门槛 |
|---|---|---|---|
| L1 | 本地保存 / 壁纸 / 复制到剪贴板自用 | 部分适用（文件名规则见 §5） | 无 |
| L2 | 送帖 / 一键分享 / OG / 落地页 | **本规格主管** | 无授权门槛（载体不含个人输入），但须不可撤回警示（§6.2） |
| L3 | 公开发布文章 / 共读 / 案例库 | 另裁 | consent_for_public_draft===true + 时间戳 + 九类 PII 扫描 + 熟人反推复核 + 人工审核，默认关闭 |

**关键澄清：送帖不是 L3。** 送帖的载体是「东方解忧笺公开版」，内容 = 主题 + 核验引文 + 出处 + 白话 + 微行动 + 标识组，不含任何用户输入，故无授权门槛。但它仍受三件事约束：字段白名单（§1）、PII 校验（§3.3）、不可撤回警示（§6.2）。

## 1. 字段白名单（唯一事实源）

以下为内部构造公开内容的数据白名单，不是各分享 API 的通道 key 清单。通道只能投影成 §3.1 的 `title/text/url` 或 `link/imgUrl/title/desc`；链接 query 仅允许枚举 `from`，不得把全部内部字段序列化进 URL。

内部公开内容构造数据**只允许**出现：

| 字段 | 允许值域 | 示例 |
|---|---|---|
| card_name | 2 字中文，来自卡牌数据 | 克己、守静、圆融 |
| themeTag | `work` / `relation` / `night` / `growth`（源自 appState.selectedScenario，缺省 work） | relation |
| quote | 本期对外分享只取 `verified` 语料原句；`needs_review` / `not_found` 不进入分享图片、文案或 OG，保留在个人/资料库页面时按出处三态展示 | 君子求诸己 |
| book / chapter | verified 条目的书名篇章 | 《论语·卫灵公》 |
| verify | L1 三态标签之一 | 本句出处经考据核验 · 悟堂考据组 |
| sage | 先贤名（中性化后） | 孔子 |
| engine | `online` / `offline`（仅驱动 §2.2 标识与 header 徽标，本身不出现在载荷） | online |

**绝对禁止**（任何分享字段、query、文件名、外发日志）：

- `userText` / `user_statement` / `statement` / 用户原始倾诉的任何形式
- `nickname` / `user_nickname` / 道号
- `case_id` / `session_id` / `uid` / 任何账号派生值
- IP / UA / 设备号 / openid
- 精确时间戳（到秒）；日期到日仅限本地下载文件名
- 聊天历史 / 日记原文 / 情境练习对话

理由：前四类分属九类 PII 与数字标识；「精确时间 + 场景」可构成定位组合，违反数据最小化。

## 2. OG 标签（`/c/<theme_tag>` 落地页）

### 2.1 服务端渲染硬约束

og meta **必须在首包 HTML 内**（FastAPI 路由返回）。微信 crawler 不执行 JS——前端动态注入的 og 标签在微信内不生效。实现二选一：

- A：`GET /c/{tag}` 按 tag 服务端渲染静态 HTML（meta + 卡面图 URL + 引导区）；
- B：同路由 UA 分流（微信 UA 返回 meta 页，普通 UA 返回 SPA）。

### 2.2 字段落法

- `og:title` = `「{quote}」· 悟堂东方解忧处`（quote 截断 12 字，省略号收尾；not_found 句禁入 title）
- `og:description` = `{book}·{chapter}｜{verify_label}｜{engine_label}`，其中：
  - 在线：`AI 生成 · 经典引文经人工考据核验`
  - 离线：`离线整理 · 经典引文经人工考据核验`
  - 来源披露固定放在 description 后缀，与卡面 L2 同文案。此处是产品设计要求，不视作单凭 OG 已完成全部法定义务的结论。
  - 纯离线定稿仅适用于全程确定性模板且引文确已核验；先有模型文本再离线降级，或将历史模型文本拼入导出物，仍按含 AI 内容保留标识与来源元数据。
  - header 徽标说明当前服务状态；卡面/OG/元数据说明该份内容实际来源。二者共享来源事实，但不能只用当前连接状态覆盖整份内容来源。
  - 纯模板不得写 `AIGC=true` 或 `TrainedAlgorithmicMedia=true`；可记录非身份化的 `ContentSource=deterministic_template`。混合生成保留 AI 来源，不能因降级清空。
- `og:image` = 该 tag 对应公开版卡面 PNG（isPublic=true 渲染：无昵称无 raw，画面已含 L1-L4 标识组）——图片自身即第二重标识

### 2.3 披露阈值与边界

- OG 任何字段不出现用户衍生信息（§1 禁止清单）；
- 不出现任何统计数字（「本周 N 人问 X」类）。若未来落地页加统计，遵守红线 3：小样本不披露精确人数；不披露「人数 + 时间 + 地域 + 议题」组合；
- description ≤ 100 字（微信截断阈值前放完关键信息）。

## 3. 一键分享 / 送帖

### 3.1 通道与载荷

- `navigator.share`（移动端原生）：`{title, text, url}`，`url = /c/<tag>?from=<channel>`，title/text 用 §2.2 模板；
- 微信 JS-SDK（onMenuShareTimeline / onMenuShareAppMessage）：link / imgUrl / title / desc 同上；签名接口不得把 uid 写入 link；
- `channel` 枚举：`wechat_session` / `wechat_moments` / `copy_link` / `gift`；其他值忽略，仅记固定事件类型，不记原值、完整 URL、IP、UA 或任何会话标识。
- 上述 JS-SDK 方法仅表达载荷契约；上线接入时由开发核对实际 SDK 支持的方法，不据此宣称旧接口仍可用。

### 3.2 送帖（原「传灯」）

- 三档固定文案（已核定）：①「看到这句，想起你——今晚早点休息。」②「这张解忧笺送给你，愿你心里也松一点。」③「不用回我，就是想让你看看这句话。」
- 纪律：固定字符串常量，**禁止任何用户输入 / 动态字段拼接**；grep 自检：送帖文案赋值处不得出现 userText / nickname / statement；
- 弹层提示（已核定）：「将送出不含你私人心事的公开版」；
- 按钮文案：「送一帖 · 递给朋友」；
- 禁止叠加任何利益激励（助力 / 集赞 / 抽奖 / 积分）——微信诱导分享红线，处罚至封号。

### 3.3 PII 双保险校验（发送前执行）

- **字段级**：内部公开构造对象的 key 必须在 §1 白名单内；API 通道对象只能用 §3.1 指定 key。出现白名单外 key → 阻断，仅记固定事件类型与汇总计数，不记 case_id、内容、请求体、完整 URL 或异常详情。
- **值级**：quote 必须能在语料库按 verify 状态命中；card_name 限 2 字中文；tag 限四枚举；拼串（title + text + url）过后端 `risk_service.evaluate`——命中 `high_risk` 阻断分享并出安全回应（不解释原因），命中 `review` 阻断并出边界提示；
- 定位：扫描是兜底，主防线是白名单——正常情况载荷恒无可扫描内容。

## 4. 危机词 / R9 过滤落点

- **落点 1（结构性，主防线）**：§1 白名单保证用户输入不进分享载荷；
- **落点 2（防御性，兜底）**：§3.3 值级扫描，调用后端 risk_service（48 高危 + 70 复核 + 12 正则同源），落点在「分享动作发出前」的前端一道 + `/c/` 路由参数校验的后端一道；
- **R9**：纯公共模板可独立供普通访客浏览；对来自当前倾诉/聊天的分享动作，源会话 `high_risk` / `review` 均 stop，不得借公共模板绕过会话阻断。任何未来「公开发布案例」入口同样一律 stop，已授权不豁免；
- 会话层 high_risk / review 只出安全/边界回应，不生成卡片，不展示该次会话的分享出口；前端状态保留该次阻断，不能切换标签或重试分享后恢复旧卡。后端不得仅信任客户端传入 `risk_status=normal`；若没有可信的会话结果，仅提供独立的固定公共模板，不声称分享的是该次回应。
- 当前版本不开放自定义分享语；若未来新增，须另做安全与隐私设计，不能仅依赖关键词扫描。

## 6. 授权门槛与不可撤回警示

### 6.1 分层澄清

送帖 / 一键分享 = L2，无 L3 授权门槛（无个人输入被公开）。L3 公开发布 = `consent_for_public_draft === true` + 时间戳 + 九类 PII 扫描 + 熟人反推复核 + 人工审核，默认关闭，输出一律「待主理人审核」，不自动发布。

### 6.2 L2 不可撤回警示（分享 / 送帖动作前一次）

「链接送出后可能被对方保存或转发，无法收回。确认送出吗？」

### 6.3 L3 授权口径（沿用 brand_tone §6，一字不改）

「内容可能被编辑成公开文章草稿；会先去掉能认出你的信息，并由主理人审核；不会自动发布。你可以不授权，不授权不影响你使用这个工具。」

## 7. `/c/` 落地页附加规则

- **可直接浏览**：禁「关注后查看 / 分享后查看 / 下载 APP 后查看」任何门槛（微信诱导关注 + 外链管理规范双重红线）；
- 页脚带：反占卜口径「这不是占卜，不预测吉凶——只是一次安静的自我觉察。」+ 固定声明「这张卡片不含任何私人倾诉」+ 品牌行；禁运势 / 吉凶 / 宜忌字样；
- 落地页为模板渲染内容，页脚同样落 §2.2 的 L2 标识（在线 / 离线同规则）；
- 落地页不设任何用户输入框——无输入即无泄露面。

## 9. 自检基线（交付前全绿）

- grep：分享 / 送帖 / OG / 文件名拼接处，`userText|statement|nickname|case_id|uid` = 0；
- grep：送帖三档文案为固定常量（无模板字符串拼接用户变量）；
- 接口：`GET /c/{tag}` 只接受 `theme_tag` + `from` 两个参数；注入 `?nickname=x&statement=y` → 响应与日志均不包含；
- 构造用例：分享参数注入测试（白名单外 key 拒绝 + 值级扫描触发各一例）；
- 构建：`_template.html` 改动后重跑 `python scripts/build_frontend.py`，`index.html` 同步；
- 联动基线：backend 用户可见串清理（另见守门人边界清单）完成后，`og:description` 的 engine_label 与 header 徽标同状态源验证一例。

## 10. 后端用户可见字符串中性化边界

| 类别 | 执行口径 | 重点位置 |
|---|---|---|
| 普通界面与模板文案 | 同修→朋友，求道者→使用者，先圣→先贤，垂示→寄语，微功课→微行动，法印→寄语，解脱→解忧；按完整句改写避免机械替换歧义 | `llm_service.py`、`rag_service.py`、`relief.py`、`card_render_service.py` |
| 角色声口 | 可保留温厚、简练等风格；不用善哉、施主、开示等形成宗教导师身份的称谓；始终说明现代文化角色演绎 | `chat_service.py`、`prompt_builder.py` |
| 教义、修习与医疗判断 | 不作宗教修习指导、占卜预测、诊断/处方/停药建议；命中边界即转介，不用角色演绎豁免 | 风险服务、系统提示与降级模板 |
| 资料库与真实原典 | 典籍原名、真实作者、核验引文不作中性替换；《景德传灯录》等书名不算旧 UI 术语残留 | 语料库、出处展示、考据注释 |
| 内部键与解析标记 | `buddhism`、`buddha`、存量 JSON/schema 键可保留；用户标题与内部解析键分离；改输出标题须同步解析器与测试 | `prompt_builder.py`、`llm_service.py`、`chat.py` |
| 账号存量 | 不批量重命名现有用户昵称/数据库列；新默认昵称中性化，公开/打印导出一律不取账户派生昵称 | `database.py`、导出接口 |
| 拼接寄语 | 模板自行拼接的句子明确为现代寄语，不加古籍引号/作者归属，不伪造核验状态 | 降级模板与分享投影 |

离线聊天没有引文时使用「离线引导模板 · 非模型生成」，不附加不存在的引文核验声明。`app.py` 状态页与启动文案不得用「高保真流式生成」代指固定模板，也不得仅凭设置了 API key 就声称模型已实际连接。
